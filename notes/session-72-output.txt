STEP 1 — THE RECIPE FOR RNO, FROM THE DOCS ONLY
(Sources: CLAUDE.md, SPEC.md, DECISIONS.md, DECISIONS-archive.md, and raw

A. Observations and target
 A1. Source: IEM ASOS download, station code RNO, routine reports only
     (report_type=3). SPEC 3.1, 3.4. Committed raw chunks:
     data/raw/iem_asos_RNO_{2021-03-24_2021-12-31, 2022, 2023, 2024,
     2025, 2026-01-01_2026-07-31}_routine.csv; each sidecar gives the
     exact URL and pull time (2026-08-19 UTC).
 A2. Truth field: tmpc (air temperature, degC). Sidecar notes; F76.
     "M" means missing. No unit conversion.
 A3. Target hour: 20:00 UTC (SPEC 3.4, 4.1, D42). RNO reports at :55
     (SPEC 3.4, F66, F76), so the expected pairing is the 19:55 report,
     offset -5 min (D44.7, F78).
 A4. Pairing rule: the NEAREST routine report to 20:00 UTC; if none is
     within 15 minutes, the day is dropped and counted (SPEC 4.5, D14).
     New code must pick the nearest explicitly (SPEC 4.5 last paragraph,
     SPEC 8.7 item 1). Non-finite values rejected at load (SPEC 8.7 item 2).
 A5. What is predicted: residual = observed - forecast, where forecast is
     the elevation-adjusted GRIB 2 m temperature (SPEC 4.2, D48.1).

B. Baseline features B (SPEC 7.2, 8.2, D48.2-D48.5, F89, F90)
 B1. Source: GFS 0.25 deg GRIB2, AWS noaa-gfs-bdp-pds, byte-range fetched
     per message (D48.5). For B, the existing gitignored cache
     data/raw/grib/ (session 37 pull for 2021-03-24..2025-07-31) is used
     (D64.6), with the committed manifests data/raw/diagnostics/session37/.
 B2. Cycle and lead: run on day D-1, cycle floor(20/6)*6 = 18z, forecast
     hour 24 + (20 mod 6) = f026 (SPEC 7.2, D48.2, F89).
 B3. Fields: TMP:2 m above ground; TCDC:entire atmosphere; UGRD and
     VGRD:10 m above ground (F90, D48.4).
 B4. Point: bilinear interpolation (four surrounding 0.25 deg points) to
     RNO's established grid point 39.537918, -119.765625 (SPEC 3.4, 7.2,
     D48.2, D48.5), longitudes handled in 0-360 form (F89's bug note).
 B5. Temperature: K -> degC, then the fixed elevation adjustment,
     corrected = raw + (orog - grid_elev)/1000 * 7.429 (D48.3). RNO's
     constant: +2.0436 degC (SPEC 5.2; correction_c in
     data/raw/diagnostics/session37/session37_elevation_correction_params.csv).
     This is `temperature_grib_c` and is also the raw-GFS rung (SPEC 5.2,
     D48.10).
 B6. Cloud cover: TCDC as GRIB reports it, percent, uncorrected (D48.5).
 B7. Wind: sqrt(U^2 + V^2) at 10 m, m/s * 3.6 -> km/h (D48.4, F90).
 B8. Season: season_sin = sin(2*pi*yf), season_cos = cos(2*pi*yf),
     yf = (day_of_year - 1)/365, or /366 in a leap year (D21.3, D48.4).

C. The four added features (SPEC 8.1, 8.2, D58 item 3, F98, F100-F102,
   F107, F111.2). All from the same GRIB source, same run (D-1 18z),
   bilinear to the same grid point, NO elevation correction on any of them
   (F98, F111.2). Intermediates stored at 3 decimals, SPFH at 6 (F111.4).
 L. TMP at 925, 850, 700 mb, f026, K -> degC (t925, t850, t700).
    t2m_raw = round(temperature_grib_c - correction_c, 3) (F98 decision 2,
    F111.2). lapse_rate_t2_t850 = round(t2m_raw - t850, 3) (F111.2).
    No transform (SPEC 8.1).
 D. RH, DPT, SPFH at 2 m, f026; DPT K -> degC (F111.2).
    dewpoint_depression_t2m = round(t2m_raw - dew_point_2m, 3) (F100,
    F108, F111.2). Transform at model time:
    dewpoint_depression_t2m_floored = max(dewpoint_depression_t2m, 0)
    (SPEC 8.1, D53, D58 item 3).
 T. PRMSL and PRES:surface at f026, and PRMSL at f023 (lead - 3) from the
    same run; Pa -> hPa, rounded to 3 decimals; pressure_tendency_3h_hpa =
    round(pressure_msl_hpa - pressure_msl_lead_minus3_hpa, 3) (F101,
    F111.2). No transform.
 R. DSWRF:surface. At RNO (lead 26) the f026 "24-26 hour ave fcst" message
    already is the 2-hour window ending at 20:00 UTC and is used directly
    (SPEC 8.2, F102). dswrf_2h_wm2 = that average, W m-2. No second
    message; dswrf_ave_to_lead_minus2_wm2 is blank by recipe at RNO (F107).
    NCEP codes DSWRF as parameter 0/4/192 in these files (F111.4).

D. Windows and complete-case rule (SPEC 8.3, D58 items 4, 5, 6; D64.2)
 D1. Train 2021-03-24 .. 2024-07-31; test 2024-08-01 .. 2025-07-31.
 D2. Complete-case set: a row is used only if every relevant column has a
     value; built over B's columns plus the columns behind D (raw
     dewpoint_depression_t2m), L, R, T (SPEC 8.3, D58 item 5). A row also
     needs its paired observation to be trained or scored (F109's
     no_obs_dropped).
 D3. The model rungs (raw GFS, B, B+D,L,R,T) are scored on the same rows
     (F109 table).

E. Persistence (SPEC 8.5, D58 item 6, D21.8, D48.9)
 E1. Persistence forecast for day D = the previous calendar day's paired
     20:00 UTC observation (same pairing rule). Past only (SPEC 2.1d). It
     may reach across the train/test boundary (D48.9).
 E2. Day basis: scored only on test days that have a previous-day
     observation (SPEC 8.5, F109's n_persist = n_final - no_prev).

GAPS AND AMBIGUITIES (docs silent or unclear) — choice made, alternatives
 G1. Nearest-report tie. SPEC 4.5 names no tie-break when two reports are
     equally near (e.g. 19:50 and 20:10). Choice: take the earlier report,
     and count ties. Alternative: the later report, or drop the day. F78
     found zero days with >1 report in the window at RNO, so probably moot.
 G2. Report with no temperature. SPEC 4.5 says "nearest routine report";
     D62 speaks of "usable reports". Choice: choose the nearest report that
     has a finite tmpc. Alternative: take the nearest report whatever its
     value, and drop the day if its tmpc is missing. The build counts
     days where the two readings differ.
 G3. Window edge. "Within 15 minutes" — choice: |offset| <= 15 min,
     inclusive. Alternative: strictly less than 15. Only a report at
     exactly :45 or :15 could be affected.
 G4. B's stored precision is not stated anywhere in the docs
     (temperature_grib_c, cloud_cover_grib_pct, wind_speed_grib_kmh).
     Choice: keep full float precision in the table, and add 3-decimal
     columns beside them. t2m_raw is computed from the 3-decimal
     temperature_grib_c (the recipe "round(temperature_grib_c -
     correction_c, 3)" implies a stored value). Alternative: compute
     t2m_raw from the full-precision value; that column is also kept
     (t2m_raw_from_full), so session 73 can compare both.
 G5. The RNO constant. D48.3's formula gives 275.08/1000*7.429 =
     2.04356932; SPEC 5.2 and the params CSV give 2.0436. Choice: 2.0436
     (the CSV value, which F107/F111 say the pipeline reads).
     Alternative: the unrounded 2.04356932.
 G6. "Bilinear". SPEC 7.2's plain gloss says "weighted by distance", which
     could be read as inverse-distance weighting. Choice: standard
     bilinear on the regular lat/lon grid (weights from the fractional
     position in each axis), as D48.5/F89 describe. Alternative:
     inverse-distance weights.
 G7. Rounding of derived L and D values. The docs write round(t2m_raw -
     t850, 3) and round(t2m_raw - dew_point_2m, 3) but do not say whether
     t850 and dew_point_2m are rounded first. Choice: use the stored
     3-decimal intermediates (F100 and F108 found the stored identity
     holds exactly on every row using the stored intermediates, which is
     what derivation from rounded values produces). Alternative: use
     unrounded intermediates, then round.
 G8. Rounding of wind speed, cloud cover and season terms: not stated.
     Choice: full precision (plus 3-decimal columns for B's GRIB values).
 G9. Unit conversions: K -> degC is taken as minus 273.15 (not stated
     numerically in the docs). Pa -> hPa as divide by 100 (F111.2).
 G10. TCDC has two "entire atmosphere" messages in some files (F97 notes
     both instantaneous and averaged variants exist for cloud-layer
     fields). B uses the cached message chosen in session 37; the build
     decodes and reports its step type, so the choice is visible, not
     assumed.
 G11. Day list. The committed pipelines built L/D/T/R only on dates the
     B dataset carries (F98, F107). Choice: build every calendar day in
     both windows and leave a missing input missing; so the one B gap
     (2022-11-30, F90) shows as a blank row, not an absent one.
 G12. Complete-case scope in the TRAIN window, and whether observations
     are part of "every relevant column". Choice: report both counts —
     feature complete-case (D58 item 5's own count) and feature + target
     complete-case (F109's n_train/n_test).
 G13. Messages with a mismatched .idx (F90's 2022-11-29 18z f026 case):
     the recipe drops and counts them (SPEC 2.2). Choice: the same.
