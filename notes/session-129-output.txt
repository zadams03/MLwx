A. D105.5 point by point

(a) What is scored. The `corrected` column, as issued. NEW: `history_events` runs
    `git log --root --no-renames -c --name-status` over every commit reachable from the clone's HEAD and
    collects every event on a path under log/. The write-once check passes only if every such path has exactly
    one event and it is an add. A shallow clone is refused. Each cycle's file is the path
    log/YYYY/MM/gfs_YYYYMMDDHH.csv; its text is read from the commit that added it (`git cat-file`), parsed
    with the same columns as `mlwx.prediction_log` (LOG_COLUMNS, parse_time, imported). Any other file under
    log/ is reported (as a second file for its cycle if its name holds a ten-digit stamp) and never scored.
(b) Outputs. Hourly: logged rows at leads 3 to 48. Daily maximum: IMPORTED `mlwx.dailymax.local_day`,
    `day_cycle`, `read_off` (D98.10(b), (c)) on the logged `corrected` and `raw_gfs`; observed maximum by
    session 106's `observed_max` (D98.10(a)); each airport's time zone from `mlwx.config.load_airports`.
(c) The bar. IMPORTED from session 106: `persistence_k`, `hourly_persistence`, `daily_persistence`, `margin`,
    `half_pass`, `look_pass`; session 97's `mae` and `mean_error` (the NumPy mean, in session 106's row order:
    cycle hour, lead, cycle). Raw GFS is the log's `raw_gfs`.
(d) Airports. The 12: `mlwx.records.has_stagec_tables` (D103.4). The 37: the airports of
    data/processed/session111_new_tables.csv, read by `mlwx.records.new_tables` after its SHA-256 check
    (D105.8). So the list is fixed and an airport added later to gfs_airports.csv is not in the test. Starts:
    the 12 at 2026-10-12T12; the 37 at 2026-10-13T18, held as a constant from F154.2 ("First 49-airport cycle"),
    checked by a test against the DECISIONS files and at run time against the log.
(e) Periods. NEW: `period_window(period, first_v17)`. A: to the cycle 6 hours before the v17 cycle, or to
    2027-07-31T18. B: from the v17 cycle to 2027-07-31T18. A row or local day belongs to the period of its
    cycle. Nothing valid after 2027-07-31T23:00 is used: such rows are counted and left out; a day whose last
    hour is later is not used (D98.10(a)); the observation lookup refuses a later time.
(f) Observations. IMPORTED `mlwx.observations.fetch_reports` and `ReportSet(live=True)`; `.nearest(valid)` at
    each valid hour needed. NEW: the request list (one request per airport and calendar month), the raw
    responses saved with URL, time and SHA-256, and the 7-day refusal. The snapshot comparison runs only after
    the score files are written.
(g) Verdicts and the claim. PASS or FAIL per airport, period and output (both halves must pass). Printed per
    output and group: "passes at N of 12 airports", "at N of 37 airports", with the smallest margin first
    (D79.1). Nothing is averaged across airports.
(h) Counted, never excluded. NEW: cycles in the window with no log file, with the reason from the state
    file's stop list; each cycle's issue lag; rows issued after their valid time, by lead; rows and days with
    no observation.
(i) Descriptive. NEW (simple groupings of the same errors): the baseline without b, mean errors, leads 3 to 24
    and 25 to 48, per cycle hour, per model manifest and code commit, and edge-of-day days counted and scored
    separately.
(j) Expectation. Printed with the result for period A and the 12: met or not met.
(k) Changes during the window. No code: see reading 3.
(l) The look. `--score` refuses unless the script is tracked by git and equal to its committed version.

B. Places where D105.5 leaves a choice open, the reading taken, and why

 1. Persistence when a cycle is issued late. The reference time is the cycle, never the issue time (D123.2;
    D100.5 says "before the run's cycle c").
 2. Which cycle's rows make a local day's forecast. Only the cycle of D98.10(b): the latest cycle c with
    c + 4 hours at or before the day's start. If that cycle has no log file, or lacks one of the day's hours,
    the day has no forecast and is counted; no other cycle stands in (D98.10(c)). A day whose cycle was in fact
    issued after the day began still counts: lateness is counted, never excluded (D105.5(h)).
 3. A model SHA-256 or code commit that changes mid-period. Every row is scored as logged, in the bar. The
    split by manifest and commit is descriptive only (D105.5(i)). The script has no switch to leave rows out:
    if an entry under D105.5(k) ever says rows after a change are treated differently, that needs a new script
    (D116.10).
 4. The window per group. The 12: every cycle from 2026-10-12T12. The 37: every cycle from 2026-10-13T18
    (F154.2). If any of the 37 has a logged row before that, or none in that cycle, the script stops: the
    record and the log would disagree, and the owner rules.
 5. `--first-v17-cycle`. Must be `none` or a 00, 06, 12 or 18 UTC hour after 2026-10-12T12 (D123.3) and not
    after 2027-07-31T18. A later v17 start is outside the window, which is the "none" case of D105.5(e), so
    the script asks for `none` instead of guessing. `--period B` with `none` is refused (period B exists only
    if v17 starts in the window).
 6. The 7 days. The period's last valid hour is the earlier of its last cycle plus 48 hours and
    2027-07-31T23:00. `--score` refuses until 7 days after it (D105.5(f)).
 7. The common sets. Hourly: every logged row of the period's cycles, at an airport in the test, valid on or
    before 2027-07-31T23:00, with an observation (D100.5(a): "the look's scored rows"). Daily: days with a
    usable observed maximum and both forecast maxima. Persistence half: the subset with a persistence value,
    both sides on that subset (D100.5(b)).
 8. A half with no rows. It cannot pass (session 106's `half_pass`), and has no margin.
 9. "A later file for the same cycle". Any file under log/ that is not the cycle's own path. D103.8 does not
    fix a correction's name, so everything else is reported and nothing else is scored.
10. "Added once and never modified or deleted". Read as: over all commits reachable from HEAD, each path under
    log/ has one event, an add. A merge that itself changes a log file is an extra event and fails. Limit: a
    clone cannot show history that was rewritten and force-pushed before the clone was made.
11. The reason for a missing cycle. The state file keeps only its last 100 stops (`MAX_STOPS`), so the script
    reads the stop list from every committed version of state/tracker_gfs.json and takes each cycle's reasons
    from there. A missing cycle with no stop gets "no reason in the state file".
12. A logged cycle that lacks rows for an airport or lead. Counted per airport ("rows missing in a logged
    cycle"); nothing is filled (SPEC 2.2).
13. Issue lag. The file's issue time is its rows' `issued_utc`. If a file holds more than one, it is reported
    and the latest is used for that cycle's lag; "issued after its valid time" is judged row by row.
14. Edge-of-day days (D105.5(i)). D106.7(f) calls its own definition "D105.5(i)'s quantity", so the same
    reading is used: the maximum's hour is the first hour holding it (a tie goes to the first hour), and the
    day is an edge day if that hour is the first or last hour of the local day; for the observed maximum the
    first usable hour holding it. NEW code (three lines), checked by a test against session 112's `peak_index`
    and `is_edge`. Session 112 is not imported because its file is not frozen at a recorded SHA-256.
15. Observation requests. From 4 days before the group's first cycle (persistence goes back at most 3 days
    hourly, and to the local day before a day's cycle daily) to the day after the period's last valid hour.
    Observations from before 2026-10-12 are therefore read at the look, for persistence only.
16. Snapshot agreement (D105.5(f)). After the score files are written: for every row of every obs/ file of
    the period's cycles, the snapshot's `obs_c` against the fresh pairing at that airport and hour. Counts
    only: equal, different, snapshot empty and fresh present, snapshot present and fresh empty. No forecast is
    involved.
17. What "--inventory passes" means. The clone is not shallow, the write-once check holds, and every cycle
    file parses as a log file whose rows fit its name (reading 18). Second files, missing cycles and late rows
    are counted and do not fail it.
18. Integrity stops. A cycle file whose columns are not the log's, whose rows name another cycle, a valid time
    that is not cycle plus lead, a lead outside 3 to 48, or the same airport and lead twice: the inventory
    fails and `--score` stops. Such a file is not in D103.8's form, and choosing how to score it would be a
    new rule; the owner rules.
19. The GFS version column. Counted per period, never used: the period comes from the cycle and
    `--first-v17-cycle` (D105.5(e)), and the config's label can lag the real change (D103.10).
