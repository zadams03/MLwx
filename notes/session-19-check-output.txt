PART 0b - the station chosen: YSDU (Dubbo), and why.
Both stations pass the basic bar - both exist in AU__ASOS with
authoritative coordinates, both report hourly on the hour with a
complete-looking week-long sample, and both are inland (neither is
coastal). The session prompt also asks for 'flat-ish, not alpine'.
Canberra (YSCB) sits at 577 m, in a valley ringed by the Brindabella
Range - the nearest ski resorts are under two hours away, and its
winter climate is noticeably shaped by that elevation and the nearby
high country. Dubbo (YSDU) sits at 275 m on the flat wheat-sheep
plains of central-west New South Wales, with no comparable terrain
complication - the closer match to DSM's flat continental profile
(294 m, D32) that the session prompt is asking this airport to be a
Southern Hemisphere counterpart to. YSDU is chosen on that basis.

Side by side with the three airports already in the project (SPEC 3.4):

  different season cycle, and 14,500+ km from the nearest of them.

PART 0c - the target hour: is local standard noon really 02:00 UTC?
==========================================================================
D37 (session 19 preamble) expects local standard noon at UTC+10 to be
02:00 UTC. This checks it against the timezone database rather than
taking it on trust, the same way F32 did for DSM.

timezone from IEM metadata : Australia/Sydney
  mid-summer (daylight saving in AU)  : 02:00 UTC = 13:00 AEDT (UTC+11)
  mid-winter (standard time in AU)    : 02:00 UTC = 12:00 AEST (UTC+10)
  standard-time offset          : UTC+10
  so local standard noon (12:00) = 02:00 UTC
  D37 expects                    = 02:00 UTC
  VERDICT                        : MATCHES

Note on daylight saving: eastern Australia observes it (AEDT, Oct-Apr).
Standard offset is read from a JULY date on purpose (mid-winter,
guaranteed standard time), the same way F32 read DSM's January date.

Note on which state/timezone: IEM's tzname for this station is
'Australia/Sydney'. New South Wales observes daylight saving; the
convention (D27/D33) uses the STANDARD offset regardless (UTC+10),
per D37 and the session prompt.

PART B6 - timezone check: is the tz=UTC request really UTC?
==========================================================================
Every IEM request in this project sends tz=UTC. The same window was
pulled a second time with tz=Australia/Sydney, so the two can be
compared. June is southern-hemisphere winter, so Australia/Sydney is
on STANDARD time (AEST, UTC+10) throughout - unlike DSM's July check,
which landed in daylight saving.

UTC-request file        : iem_asos_YSDU_2024-06-01_2024-06-04_routine-tmpc-tmpf.csv
local-request file      : iem_asos_YSDU_2024-06-01_2024-06-04_routine-localtime.csv
rows, UTC request       : 72   first 2024-06-01 00:00:00, last 2024-06-03 23:00:00
rows, local request     : 72   first 2024-06-01 00:00:00, last 2024-06-03 23:00:00

The two requests use the same start/end date strings but under
different tz, so they do not cover the same physical hours at their
edges. Rather than comparing by row position (which breaks at the
edges), each local-file timestamp is shifted by a candidate number of
hours and matched against the UTC file's timestamps directly, and the
temperature values are compared at matching physical instants.

  shift        matching timestamps   values equal
  local - 6h        66                     0  (0.0%)
  local - 7h        65                     7  (10.8%)
  local - 8h        64                    10  (15.6%)

  local -10h        62                    62  (100.0%)
  local -11h        61                    18  (29.5%)
  local -12h        60                    10  (16.7%)
  local -13h        59                     7  (11.9%)
  local -14h        58                     0  (0.0%)

  best match: local time minus 10 hours lines up with the UTC
              series (100.0% of 62 comparable hours identical).
  Expected: Australia/Sydney standard offset UTC+10, so local = UTC + 10,

   elevation 275.0 m, timezone Australia/Sydney - flat inland
   country, the closer match to DSM's continental profile than
   Canberra's elevated, hill-ringed setting. Chosen after comparing

   values null, and the first hour carrying a real value is exactly
   2021-03-24 00:00 UTC - the same hour as EGLC, LFPG and DSM, to the

   airport on a fourth continent gives the same answer.

4. Target hour. Australia/Sydney's standard offset is UTC+10, so
   local standard noon is 02:00 UTC year-round, matching D37's
   expectation exactly. Daylight saving is ignored per the D27/D33
   convention, so the target stays a fixed UTC hour all year.

5. gfs_global vs gfs_seamless: IDENTICAL in both windows tested, 0
   value differences across every compared hour. F6's original
   Europe-only reasoning happens to hold here too, but for the
   opposite continent's reason - Australia, like Europe, has no
   CONUS-only NCEP model for gfs_seamless to blend in. F40's DSM

   the same way it did for all three other airports.

8. Target-hour availability (02:00 UTC, D14 applied). Every single
