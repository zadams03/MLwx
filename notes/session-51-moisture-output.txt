Three design decisions confirmed before any pull runs (session prompt
Task 2):
  1. dewpoint_depression_t2m uses the RAW 2 m temperature (t2m_raw),
     recovered algebraically as t2m_raw = temperature_grib_c -
     correction_c (each airport's own fixed D48.3/F90 constant) --
     NOT the elevation-corrected temperature_grib_c. No new 2 m-
     temperature GRIB pull is needed.
  2. NO elevation/lapse-rate correction is applied to RH, DPT or SPFH
     anywhere in this script. SPEC 7.2's 7.429 degC/km correction is a
     temperature-only fix for a surface grid-cell elevation mismatch;
     it does not apply to a humidity ratio, a specific humidity, or a
     dew point used to form a depression -- bilinear horizontal
     interpolation only, same as cloud cover/wind speed (F91) and the
     upper-air pressure levels (F98).
  3. No raw GRIB2 bytes are kept on disk (disk-space-forced, as in
     F98) -- fetch, decode with eccodes, discard; a per-request
     manifest (no bytes) stands in as the provenance record.
