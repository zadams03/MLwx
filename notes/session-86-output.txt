1. THE SHARED FRAME (all columns)
- Source: GFS 0.25 degree GRIB2, AWS bucket noaa-gfs-bdp-pds, path
  gfs.YYYYMMDD/CC/atmos/gfs.tCCz.pgrb2.0p25.fFFF, with its .idx beside it
  (session37_grib_pull.py l.94-99; session76_grib_pull.py l.133-135).
  Each message is fetched by byte range taken from the .idx, never the whole file.
- Lead convention (SPEC 7.2; F89): for target hour H on day D, the run of day D-1 at cycle
  floor(H/6)*6, forecast hour 24 + (H mod 6)
  (session37_grib_pull.py l.88-91; session49_upper_air_pull.py l.98-101).
- .idx match: exactly one line with the variable, the level and the step string "N hour fcst"
  (this excludes the "24-26 hour ave fcst" TCDC entry); a message is complete only if it
  starts with GRIB and ends with 7777 (session37_grib_pull.py l.119-133;
  session76_grib_pull.py l.167-177, 270).
- Grid point and interpolation (SPEC 8.8 G6): the four surrounding points from eccodes
  codes_grib_find_nearest; standard bilinear (fraction along latitude and along longitude, not
  inverse distance); a negative longitude is shifted by +360 before the weight is taken; if the
  four points are not a 2x2 box and one span is zero, the nearest point's value is used
  (session37_decode.py l.80-118; session49_upper_air_pull.py l.148-171; session76_grib_pull.py
  l.180-207). Grid points come from SPEC 3.4 (table below).
- Checks on each message: identity codes, run date and time, and full validity date and hour
  (session76_grib_pull.py l.210-233). The v16-window scripts for L and D checked the date but
  not the hour (A68b-05); no effect on a value.
- Missing days: a target day is dropped, and counted, if any message it needs is missing, fails
  the checks or is not finite. Nothing is filled (SPEC 2.2). The record's family files (B, L, D,
  T, R) each drop a day if any of their own messages fails, so a day is in the record only if all
  of them decoded. The new code fetches the same messages (14 at lead 26, 15 at lead 24) and
  drops a day the same way, so its row set matches the record's.

2. B
- temperature_grib_c = round((K - 273.15) + correction_c, 3), from TMP 2 m above ground at the
  standard lead. It is also the model column "temp" and the raw-GFS (GRIB) rung
  (session37_decode.py l.154, 164; session76_build.py l.162; SPEC 8.8 G4).
  Stored at 3 decimals, rounded AFTER the constant is added.
- correction_c: read from the params CSV, 4 decimals as stored, never the unrounded formula
  value (SPEC 8.8 G5): data/raw/diagnostics/session37/session37_elevation_correction_params.csv
  (EGLC, LFPG, DSM, YSDU, RNO) and data/raw/diagnostics/session76/
  session76_elevation_correction_params.csv (SFO). It applies to temperature only.
- cloud_cover (cloud_cover_grib_pct) = round(TCDC entire atmosphere, 3), used as GRIB reports it.
- wind_speed_10m (wind_speed_grib_kmh) = round(sqrt(UGRD^2 + VGRD^2) * 3.6, 3), 10 m above
  ground, m/s to km/h (session37_decode.py l.155).
- season_sin, season_cos = sin, cos of 2*pi*year_fraction(date), where year_fraction =
  (day_of_year - 1) / (366 in a leap year, else 365). Full float precision, not rounded
  (session62_reserved_confirm.py l.217-219, 224).

3. L (lapse rate)
- Fields: TMP at 925, 850 and 700 mb, standard lead, bilinear only (no elevation correction:
  fixed pressure surfaces) (session49_upper_air_pull.py l.60-63, F98).
- t2m_raw = round(temperature_grib_c - correction_c, 3), built from the stored 3-decimal value.
- lapse_rate_t2_t850 = round(t2m_raw - (T850_K - 273.15), 3). T850 is NOT rounded before the
  subtraction (session49_upper_air_pull.py l.299-301, 384; SPEC 8.8 G7). t925, t850 and t700
  are stored as round(K - 273.15, 3) separately.

4. D (moisture)
- Fields: RH, DPT, SPFH, all 2 m above ground, standard lead (session51_moisture_pull.py
  l.96-100). All three are fetched; a day is dropped if any fails, as in the record.
- dewpoint_depression_t2m = round(t2m_raw - (DPT_K - 273.15), 3), DPT not rounded first (G7).
  The model column is the FLOOR TRANSFORM: dewpoint_depression_t2m_floored = max(depression, 0)
  (SPEC 8.1; session62_reserved_confirm.py l.360, build_complete_case).
  relative_humidity_2m and dew_point_2m are stored at 3 decimals, specific_humidity_2m at 6.

5. T (pressure tendency)
- Fields: PRMSL mean sea level and PRES surface at the standard lead, and PRMSL at lead - 3 from
  the SAME run (f021 at lead 24, f023 at lead 26) (session53_pressure_pull.py l.91-98, 349-450).
- Each of the three is stored as round(Pa / 100, 3). pressure_tendency_3h_hpa =
  round(msl_hpa - msl_lead_minus3_hpa, 3), from the two ROUNDED values
  (session53_pressure_pull.py l.473-480; session76_build.py l.186-191).

6. R (shortwave radiation)
- Field: DSWRF surface. It exists only as a time-averaged "ave fcst" message; no instantaneous
  variant exists (F102). The target is the 2-hour average ending at the target hour.
- Window start = 6 * ((lead - 1) // 6) (the 6-hour reset marks).
- Lead 26 airports (YSDU, RNO, SFO): the native "24-26 hour ave fcst" message at f026 already is
  the 2-hour window. dswrf_2h_wm2 = round(value, 3). No second message.
- Lead 24 airports (EGLC, LFPG, DSM): the native message at f024 is "18-24 hour ave fcst" (6 h).
  A second message at f022 is "18-22 hour ave fcst" (4 h). Energy is subtracted:
  dswrf_2h_wm2 = round((ave_f024 * 6 - ave_f022 * 4) / 2, 3), using the UNROUNDED decoded values
  (session55_radiation_pull.py l.552-562; F102). The two raw endpoints are stored at 3 decimals.
- Units W m-2, no conversion. At the lead-26 airports the "minus 2" column is blank (not
  applicable), never a filled zero.

7. KSFO (session76_grib_pull.py, session76_build.py; F116)
- Same recipe as RNO (also cycle 18z, lead 26, target 20:00 UTC): 14 messages per day, one
  fetch-decode-discard pass. Same formulas and rounding as sections 2 to 6. Its constant is
  +0.6944 degC. Its observation is paired to the nearest report, a tie keeping the earlier one.
  The file scripts/session76_build.py is the newest copy of the whole recipe, and the new script
  copies from it.

8. THE OBSERVATION AND THE PREVIOUS-DAY OBSERVATION
- Truth: IEM ASOS routine reports (report_type=3), tz=UTC, tmpc in degC. Query form (any
  data/raw/iem_asos_*.meta.txt): station, data=tmpc, data=dwpc, day-level start, EXCLUSIVE day-level
  end, latlon=yes, elev=yes, missing=M, trace=T, direct=no.
- Historical pairing (five earlier airports; session62_reserved_confirm.py l.321-344): each
  report is assigned to its nearest whole hour (a report at :30 goes to the next hour); it is
  kept if that hour is the target hour, it is within 15 minutes INCLUSIVE (G3), and its tmpc is
  not M, blank, T or None (skipped BEFORE the choice, G2); the LAST kept report in the file wins
  (G1). It differs from "nearest" only on a day with two usable reports in the window (1 day in
  the whole record, equal temperatures, D62).
- New pairing (SPEC 8.7 item 1; KSFO's, session76_build.py l.230-256): the nearest usable
  routine report within 15 minutes inclusive. A tie keeps the earlier report and is counted.
- Previous-day observation for persistence (session62_reserved_confirm.py l.394-404;
  SPEC 8.5): the paired observation at the target hour of day D-1. It may be missing; then
  persistence is not scored on that day and the day is counted.
- Non-finite tmpc is rejected at load and counted (SPEC 8.7 item 2).

9. ROUNDING AND PRECISION SUMMARY (SPEC 8.8 G4, G5, G7)
