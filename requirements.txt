# No script imports scikit-learn directly, though importing lightgbm loads

#
# ---------------------------------------------------------------------------
# OpenMP note (the thing that will trip up anyone setting this up fresh)
# ---------------------------------------------------------------------------
# LightGBM on macOS needs the OpenMP library libomp.dylib. It is a system
# library, not a Python package, so pip cannot install it. The standard fix
# is Homebrew:
#
#     brew install libomp
#
# Older scripts keep a loader workaround from before Homebrew was installed:
# they point the dynamic loader at the copy of libomp.dylib inside
# scikit-learn's macOS wheel, then restart the interpreter once. Those
# scripts are part of the record, so they cannot be edited. The workaround
# only lets the library load and changes nothing about the model (repeat
# runs were byte-identical, DECISIONS F14, F15, Q16). It is harmless when
# Homebrew's libomp is present. Setup steps are also in README.md.
#
# What session 98b found (DECISIONS F140): Homebrew 7.0.8 with libomp
# 23.1.3. With the workaround switched off, the session 97 cross-validation
# script still reproduced F109's six recorded MAEs exactly (6 of 6), and its
# EGLC scores were byte-equal to the committed file. So scripts from session
# 99 on may import lightgbm directly (DECISIONS D90.9).
#
# scikit-learn stays pinned for one reason: the older scripts' workaround
# uses its copy of libomp.dylib.
