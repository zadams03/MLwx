# numpy      - arrays and arithmetic (the modelling scripts)

# exactly, not approximately.
#
# scikit-learn is NOT imported by any script. It is here for one reason only:
# the OpenMP note below.
#
# ---------------------------------------------------------------------------
# OpenMP note (the thing that will trip up anyone setting this up fresh)
# ---------------------------------------------------------------------------
# LightGBM's macOS build will not import without the OpenMP runtime library
# libomp.dylib. It is not part of macOS and pip cannot install it, because it
# is a system library rather than a Python package. The normal fix is Homebrew:
#
#     brew install libomp
#
# This machine has no Homebrew, so a workaround is used instead: scikit-learn's
# macOS wheel ships its own copy of libomp.dylib, and the model scripts point
# the dynamic loader at that copy and restart the interpreter once. That block
# sits at the top of the modelling scripts, clearly commented (setup steps are
# also in README.md). It changes nothing about the model - it only lets the
# library load - and repeat runs were byte-identical (DECISIONS F14, F15, Q16).
#
# So: scikit-learn is pinned here because it is currently the source of
# libomp.dylib on this machine. If libomp is installed properly, scikit-learn
# is no longer needed and the workaround block becomes a no-op (it checks
# whether the file exists before doing anything).
